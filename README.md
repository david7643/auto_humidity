# 스마트 가습기 제어기

개발계획서 v1.1을 기반으로 작성한 **Arduino Uno R3 + W5100 Ethernet Shield + SHT45 + IR 송수신기** 펌웨어입니다. 기존 DHT11·LCD 스케치를 대체합니다. LCD와 DHT11은 사용하지 않습니다.

2026-10-24 기준 최신 펌웨어를 Uno R3(COM8)에 업로드하고 웹 API 응답·SHT45 측정·저장된 IR 신호 3개 유지를 확인했습니다. 분무 기억·취침 상태 전이는 자동 테스트를 통과했으며, 변경된 동작의 실제 기기 통합시험과 장시간 안정성 검증은 남아 있습니다.

`.tools`의 CLI·라이브러리·빌드 산출물은 Git에 포함하지 않습니다. GitHub에서 처음 내려받았다면 아래의 `setup.ps1`을 먼저 실행하세요.

## 구현 기능

- SHT45를 1초마다 측정하고 온도/습도 CRC 검증. 변환 대기 중 다른 작업을 수행합니다.
- 모바일 브라우저에서 2초 주기로 온습도·추정 상태·오류 조회. 인터넷/CDN 없이 사용합니다.
- 목표 40~47% RH 및 자동 모드 선호값, IR 3개 버튼을 EEPROM에 저장합니다. 실제 전원·취침·기억 단계는 RAM에서만 관리합니다.
- 전원·분무량·취침 IR 학습 → 시험 송신 → 사용자 정상 반응 확인 → 영구 저장.
- **실제 상태 보정은 IR 송신 없이 내부 상태만 변경하며 자동 제어를 PAUSED로 전환합니다.**
- 60초 상당 EMA, 히스테리시스, 최소 유지시간, 1/2단계 제어.
- 센서 데이터 30초 이상 끊기면 PAUSED. 복구 후에도 사용자가 재개합니다.
- 부팅 시 전원·단계 UNKNOWN, PAUSED. 저장된 자동 선호값만 표시하며 자동 운전을 바로 재개하지 않습니다.
- 최근 이벤트 6개와 IR/전원/단계 송신 횟수. 이벤트·횟수·상태는 재부팅 시 초기화됩니다.
- 입력 제한과 상태 버전 검사로 중복 토글과 오래된 요청을 차단합니다. 제어 키는 사용하지 않습니다.

## 배선

전원을 끄고 배선하세요. IR 수신기는 제품마다 핀 순서가 다릅니다.

| 기능 | Uno R3 연결 |
|---|---|
| W5100 쉴드 | Uno에 장착, LAN 케이블로 공유기 연결 |
| SHT45 SDA / SCL | A4 / A5, 전압 호환 회로 경유 |
| SHT45 VCC / GND | 해당 모듈 사양에 맞는 전원 / 공통 GND |
| VS1838B IR 수신 OUT | D2, VCC·GND 핀 배열은 부품 사양 확인 |
| IR 송신 트랜지스터 입력 | D3, 베이스 저항 경유 |
| Ethernet CS / SPI | D10 / D11~D13, 다른 용도 사용 금지 |
| SD CS | D4, SD 미사용 및 HIGH 유지 |

**SHT45 칩은 5V용 센서가 아닙니다.** 모듈 자체가 5V 보드와 I2C 연결을 지원하는지 확인하세요. 불명확하면 센서 측 3.3V / Uno 측 5V 양방향 I2C 레벨 시프터를 사용하세요. Uno Wire의 내부 풀업도 고려해야 합니다. DHT11의 D2 배선은 제거해야 IR 수신기를 연결할 수 있습니다.

IR LED를 D3에서 직접 구동하지 마세요. NPN 트랜지스터(S8050 등)의 이미터는 GND, 컬렉터는 IR LED의 음극, LED 양극은 전류 제한 저항을 거쳐 전원에 연결합니다. D3은 베이스 저항을 거쳐 베이스에 연결합니다. **실제 트랜지스터 핀 배열과 LED 허용 전류에 맞춰 저항값을 결정**하세요. 모든 GND는 공통입니다. 전원과 회로는 분무·물기에서 떨어뜨려 설치하세요.

## 네트워크 설정

`Config.h`에서 다음 값을 집 공유기에 맞게 수정하세요.

```cpp
IP      = {192, 168, 0, 50};
GATEWAY = {192, 168, 0, 1};
SUBNET  = {255, 255, 255, 0};
```

위 IP는 예시입니다. 같은 서브넷에서 **사용하지 않는 주소를 DHCP 배정 범위 밖에 지정**하세요. MAC은 기기별로 중복되지 않아야 합니다. DHCP의 긴 대기를 피하려고 이 구현은 정적 IP를 사용합니다.

웹 주소는 설정한 `http://IP주소`입니다. 스마트폰은 같은 공유기의 Wi-Fi에 연결해야 합니다. 게스트 Wi-Fi의 기기 격리는 해제하거나 일반 내부망을 사용하세요. 포트 포워딩은 하지 않습니다.

제어 키나 로그인 없이 웹 화면에서 바로 조작합니다.

## 설치·빌드·업로드

처음 내려받은 프로젝트는 폴더명을 `auto_humidity`로 유지하세요. 스케치 파일명과 같아야 합니다. Windows PowerShell에서 해당 폴더를 열고 의존성을 설치합니다.

```powershell
.\setup.ps1
```

컴파일만 수행:

```powershell
.\build.ps1
```

배선과 Config.h 확인 후 업로드:

```powershell
.\.tools\arduino-cli\arduino-cli.exe board list
.\upload.ps1 -Port COM8
```

`COM8`은 마지막 업로드에서 확인한 포트입니다. 연결 환경에 따라 달라지므로 `board list`의 실제 포트로 바꾸세요. 스크립트는 컴파일 실패 시 업로드하지 않습니다. PowerShell 실행 정책으로 차단되면 현재 프로세스에만 `Set-ExecutionPolicy -Scope Process Bypass`를 적용할 수 있습니다.

다른 PC에서 의존성을 준비하려면 `setup.ps1`을 실행하세요. 인터넷이 필요하며 Arduino AVR 보드 코어는 Arduino 기본 데이터 폴더에, 라이브러리는 프로젝트의 `.tools/user`에 설치됩니다. 검증 버전은 `arduino:avr 1.8.8`, `Ethernet 2.0.2`, `IRremote 4.7.1`입니다. Arduino IDE를 이용한다면 같은 라이브러리를 IDE 라이브러리 관리자에도 설치해야 합니다.

웹 수정 후에는 다음 명령으로 압축 헤더까지 갱신합니다(Python 필요).

```powershell
.\build.ps1 -RepackWeb
```

## 처음 사용하는 순서

1. SHT45, 쉴드, IR 회로 배선 및 전압 호환성을 확인합니다.
2. Config.h의 IP·게이트웨이를 설정하고 업로드합니다.
3. 브라우저에서 웹을 엽니다. 센서는 정상값 10개 수신 후 제어 준비 상태가 됩니다.
4. 학습 대상 버튼을 선택하고 '학습 시작' 후 15초 안에 원래 리모컨 버튼을 한 번 누릅니다.
5. '시험 송신'으로 실제 반응을 확인하고, 정상일 때만 영구 저장합니다. 각 버튼마다 반복합니다.
6. 가습기는 마지막 분무 단계를 기억합니다. 고정 ON 기본 단계와 '취침은 항상 1단계 지정' 설정은 제거했습니다.
7. 가습기 실제 전원·분무·취침 상태를 보정합니다. OFF에서는 마지막으로 기억한 단계를, 취침 ON에서는 현재 분무 1단계와 취침 전 복원 단계를 입력합니다. 모르는 값은 모름으로 둡니다. 보정은 IR을 보내지 않습니다.
8. '자동 제어 재개'를 누릅니다. 처음 OFF로 보정했다면 최소 OFF 15분을 기다립니다.

자동 제어 진입에 필요한 조건이 부족하거나 다른 화면에서 상태를 변경했으면 HTTP 409가 표시됩니다. 화면을 확인한 후 다시 조작하세요. **실패한 토글 요청은 브라우저가 자동 재전송하지 않습니다.**

학습 시작과 수신, 시험 송신은 실제 가습기 상태에 영향을 줄 수 있으므로 내부 상태를 UNKNOWN으로 바꿉니다. 학습 중에는 저장된 버튼 송신과 자동 제어가 차단됩니다. 취소·완료 후에도 일시정지 상태이며, 다시 실제 상태를 보정하세요.

## 자동 제어 규칙

기본 목표 T=45%일 때:

| 동작 | 조건 |
|---|---|
| OFF → ON | EMA ≤42%, OFF 유지 15분, 전원 코드·기억한 단계·취침 해제 확인됨 |
| ON → OFF | EMA ≥48%, ON 유지 5분 |
| 1 → 2단계 | EMA ≤40%, 분당 EMA 변화율 ≤0, 단계 유지 5분 |
| 2 → 1단계 | EMA ≥43%, 단계 유지 5분 |
| 고습 보호 | 최신 유효 측정값 ≥50%가 3회 연속이면 일반 ON 유지시간 무시 |

판단 주기는 5초이며 IR 최소 송신 간격은 1.5초입니다. 일반 모드에서 끄면 직전 분무 단계를 RAM에 기억하고, 켜면 그 단계를 복원한 것으로 추정합니다. 2단계로 재시작해도 즉시 1단계로 강제 변경하지 않고 기존 습도·단계 유지시간 규칙을 적용합니다. 자동 단계 조정에는 분무 버튼만 사용하며 취침 버튼은 자동 송신하지 않습니다.

전원 UNKNOWN 또는 취침 작동/UNKNOWN이면 자동 제어 진입을 차단합니다. 취침이 해제된 ON/단계 UNKNOWN에서는 단계 토글을 금지하지만 습도에 따른 전원 정지 판단은 가능합니다. OFF에서 기억된 단계가 UNKNOWN이면 자동 재시작을 차단합니다. 기기 상태·기억 단계는 EEPROM에서 복원하지 않으므로 MCU 재부팅 후 실제 상태 보정이 필요합니다.

취침 버튼은 토글입니다. 진입하면 분무 1단계, 해제하면 취침 전 단계로 돌아갑니다. **취침 중 전원 버튼 첫 입력도 취침 해제만 수행하며 전원은 ON입니다. 다시 눌러야 OFF가 됩니다.** 이 두 입력은 별개의 수동 조작이며 자동 연속 송신하지 않습니다. 취침 해제로는 최소 ON 유지시간을 초기화하지 않습니다. 취침 여부가 UNKNOWN인 ON에서 전원을 송신하면 실제로 종료했는지 취침만 해제했는지 알 수 없으므로 전원을 UNKNOWN으로 바꿉니다. 취침 중 분무 버튼의 효과도 미검증이므로 단계·취침을 UNKNOWN 처리합니다.

MANUAL·PAUSED·학습 중에는 자동 IR을 보내지 않으며 고습 여부만 표시합니다. 고습 경로도 센서가 제어 준비 상태여야 합니다. 상태 보정 시 유지시간은 보정 시점부터 보수적으로 다시 계산합니다.

IR은 단방향입니다. 송신 횟수는 **명령을 보낸 횟수**이며 실제 전원 전환을 실측한 값이 아닙니다. 표시와 실제 상태가 다르면 웹에서 보정하고 명시적으로 재개하세요.

## IR 지원 범위와 제한

- 기본 표준 압축 저장: NEC / NEC2 / Onkyo / Samsung / Sony. 프로토콜·주소·명령·비트 수·반복 설정을 보존합니다.
- 기타 프로토콜: RAW 수신 및 단일 프레임 송신을 시도합니다. 최대 100구간, 각 구간 12ms 이하, 총 200ms 이하만 허용합니다. 초과·수신 버퍼 넘침·패리티 오류 신호는 거부합니다.
- RAW 기본 반송파는 38kHz입니다. 수신 모듈은 반송파 주파수를 측정하지 못하므로 필요하면 시험 화면에서 30~60kHz로 설정합니다.
- RAW의 여러 프레임·복합 명령·장시간 공백·자동 반복 학습은 지원하지 않습니다. RAW 반복 입력은 0만 허용합니다.
- 표준 프로토콜은 추가 반복 0~3회를 시험할 수 있습니다. Sony는 기본 추가 2회입니다. 반복 설정은 기기의 실제 반응으로 검증하세요.
- 확장 프로토콜 스위치 `HUMIDIFIER_EXTENDED_IR`는 기본 0입니다. 1로 켜면 RC5/RC6/Panasonic/JVC/LG를 추가하지만 **현재 전체 UI와 함께 Uno 플래시 용량을 초과하므로** 보드·화면 크기 조정 없이 켜지 마세요.
- IRremote 버전이나 EEPROM 구조를 바꾸면 Storage.h의 SCHEMA도 올리고 신호를 다시 학습하세요.

## 저장·통신 정책

설정은 CRC-16과 2개 슬롯·순번으로 저장해 저장 중 전원 차단 시 이전 정상 설정을 복구합니다. IR은 버튼별 CRC/커밋 표시가 있으며 저장 중 전원이 끊기면 해당 버튼이 미학습으로 판정될 수 있어 재학습이 필요합니다. IR 레코드까지 이중 저장하지는 않습니다.

EEPROM은 값이 변경되거나 학습 저장을 확정할 때만 씁니다. EEPROM 기록과 IR 송신은 짧은 동기 작업으로, 이때 측정·웹 응답에 지연이 발생할 수 있습니다. 나머지는 주기 실행이며 HTTP 연결은 4초 제한, 요청 처리량은 루프당 64바이트로 제한합니다. W5100 재전송과 연결 종료 제한도 설정하지만 실제 LAN 장애 시 지연 상한은 하드웨어 통합시험에서 검증해야 합니다.

웹 페이지는 플래시의 gzip 데이터이며 SD가 필요 없습니다. 폴더가 닫히거나 브라우저가 없어도 이미 AUTO로 시작한 제어는 Arduino에서 계속 실행됩니다.

## API

GET `/`, `/api/status`, `/api/ir/status`, `/api/events`를 제공합니다. 상태는 온습도를 0.01 단위 정수로 반환하며 실제 정밀도가 0.01이라는 뜻은 아닙니다. 시각은 부팅 후 경과초, `age`는 마지막 정상 측정 후 밀리초입니다. `age=4294967295`는 아직 정상 측정이 없음을 뜻합니다. 시각은 millis() 기준으로 약 49.7일마다 순환하며 제어용 경과시간 비교는 오버플로에 대응합니다.

모든 변경 요청은 POST와 정확한 `Content-Type: application/x-www-form-urlencoded`가 필요합니다. 인증 헤더는 필요하지 않습니다. 본문에는 마지막 조회 상태의 `rev`를 `r`로 포함해야 합니다. 성공한 요청과 동일한 `r`의 재요청은 409로 거부됩니다. 숫자 필드만 사용하며 본문 최대 191바이트, 헤더 전체 1200바이트, 한 줄 최대 191바이트입니다.

| 경로 | 추가 본문 필드 |
|---|---|
| `/api/target` | `a=40..47` |
| `/api/mode` | `a=0` 수동 / `1` 자동 / `2` 일시정지 |
| `/api/state/sync` | 필수 `a=0/1/2` 전원 모름/OFF/ON, `b=0/1/2` 현재 또는 OFF 시 기억 단계, `c=0/1/2` 취침 모름/해제/작동, `d=0/1/2` 취침 해제 후 복원 단계. a=0이면 b=c=d=0. 취침 작동은 ON·b=1만 허용. 취침 작동이 아니면 d=0 |
| `/api/ir/send` | `a=0` 전원 / `1` 분무 / `2` 취침 |
| `/api/ir/learn` | `a=0..2` 학습 대상 |
| `/api/ir/test` | `a=0..3` 추가 반복, `b=30..60` RAW 주파수 |
| `/api/ir/save` | `a=1` 실제 정상 반응 확인 |
| `/api/ir/cancel` | 추가 필드 없음 |
| `/api/ir/delete` | `a=0..2` 삭제 대상 |
| `/api/profile` | 폐기. 410 응답. 기존 고정 시작 단계 설정은 사용하지 않음 |

예: `r=12&a=2&b=1&c=2&d=2`는 ON/취침 중 1단계, 취침 전 2단계로 보정합니다. `r=12&a=1&b=2&c=1&d=0`은 OFF/기억 2단계/취침 해제입니다. IR은 보내지 않고 일시정지합니다. 상태의 `sleep=0/1/2`는 모름/해제/작동, `remembered`는 일반 모드의 기억 단계, `resume`은 취침 전 복원 단계이며 0은 모름입니다. OFF일 때 현재 분무 `l`은 0입니다. `src=0/1/2`는 미확인/사용자 확인/IR 추정입니다. `wanted`는 저장된 자동 선호값, `m`은 실제 모드입니다. 기존 UI의 sleep 체크박스와 숫자 의미가 바뀌었으므로 펌웨어 업데이트 후 페이지를 새로고침하세요.

EEPROM 레이아웃과 IR 스키마를 유지하여 기존 목표 설정과 학습 신호를 보존합니다. 이전 고정 시작 단계·취침 설정 두 바이트는 예약 영역으로 남기고 무시합니다.

```powershell
.\tests\run.cmd
python tests/test_assets.py
```

펌웨어 테스트는 Visual Studio 2022 C++ 도구로 실제 Firmware.cpp를 가짜 하드웨어에 연결해 실행합니다. 상태 보정의 IR 미송신, 상태 버전 충돌, 송신 간격, 학습·시험·저장, 센서 CRC·장애 복구, EEPROM 중단 복구, 임계값·유지시간·millis() 오버플로를 검사합니다. `tests/test_web.cjs`는 Node.js로 브라우저 로직·요청 본문·재시도 금지를 검사합니다. 예: `node tests/test_web.cjs`.

검증된 Uno 빌드의 메모리 수치는 VALIDATION.md에 기록합니다. 전역 RAM 이외에 실행 중 스택·인터럽트 메모리가 필요하므로 컴파일 성공만으로 장시간 안정성이 검증되지는 않습니다.

**확인 완료:** 최신 버전 업로드, 웹 API 응답, SHT45 정상 측정, 기존 IR 저장 슬롯 유지. 사용자는 기존 회로에서 IR 수신·근거리 송신 동작도 확인했으나 원하는 2m 송신 거리는 확보되지 않았습니다.

**아직 필요한 실제 시험:** SHT45 전기적 적합성, LAN 장애 복구, 새 상태 모델과 실제 가습기 반응의 일치, UNKNOWN 차단, 센서 분리·복구, EEPROM 저장 중 전원 차단, IR 송신 거리 개선, 습도 제어·소음 비교 및 24~72시간 연속 운전. 계획서의 추세 예측 조기 정지는 2차 최적화 항목으로 남겨 두었습니다.
